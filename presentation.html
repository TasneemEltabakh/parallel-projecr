LocalJobRunner runs the same Java code as the YARN path. The 5.4× speedup is pure overhead removal — not an algorithmic change.

06 / 07
Why the gap?

Each tool is optimal for a different scale of problem.

MPI · 0.6 ms
Native C, shared memory, no framework overhead. Built for one machine or a tight cluster where everything fits in memory.
Sequential · 3 ms
Same compiled code, one thread. Single-machine baseline. If your data fits and you're not bandwidth-bound, this is hard to beat.
Hadoop · 19 s
~15 s of fixed framework overhead per job. Built for petabytes on thousands of nodes, where that overhead amortises over hours of compute.

On 16 MB on one laptop, sequential C wins. The same Hadoop code would scale to TB-inputs on a real cluster without changes — that's what we're paying for.
